# AI provider strategy

OrkiCAD AI is **local-first, provider-neutral and opt-in** for cloud inference.

## Target adapters (planned, not integrated)

| Adapter | Use case | Authentication |
| --- | --- | --- |
| Ollama | Local structured parameter extraction / generation | Configurable local URL; default no cloud |
| OpenAI | Optional cloud-assisted interpretation | User-provided API key |
| Anthropic Claude | Optional cloud-assisted interpretation | User-provided API key |
| Google Gemini | Optional cloud-assisted interpretation | User-provided API key |

## Common contract

Input: a natural language request plus allowed part schema and manufacturing constraints.

Output: **schema-validated JSON parameters** (part type, measurements, units, tolerances and assumptions). Provider output must not execute directly as Python, SCAD, shell or arbitrary system commands. Geometry is generated by controlled, deterministic components. If important measurements are unspecified, return an explicit request for clarification or a clearly marked default.

## Routing

- Default to the explicitly selected local Ollama model when available.
- Remote routing is an **explicit user choice**; never silently send prompts or drawings externally.
- Per-provider timeout, cost/token limits, retries, request logging and manual fallback.
- Support **no-provider** mode for manual parametric design.
- Provider capabilities and names will be verified against their official APIs during implementation.

## Security and privacy

- Never commit or log API tokens, credentials or private drawings.
- Store secrets in OS credential store / environment variables, not in workflow JSON.
- Provide a preview of data that may leave the machine; allow local-only operation.
- Minimize personal data, document cloud-provider processing in the UI, and disclose any provider-specific retention terms.
- Test with fake provider adapters in CI; no real API keys in automated public builds.
