# OrkiCAD multilingual interface

## Implemented in Studio prototype

- A visible language selector in the header supports **Español (es)** and **English (en)**.
- The initial language follows the browser locale; Spanish locales use Spanish and other locales currently fall back to English.
- All core labels for the component form, field names, download actions, mesh viewer and frontend error messages have translations.
- Switching languages updates labels without resetting the CAD parameters or the current STL.
- Translation keys live in `studio/frontend/src/i18n.ts`.

## Architecture principles

- CAD JSON schema keys, numeric dimensions and file formats remain language-neutral, regardless of UI language.
- User-visible labels are translated; technical identifiers such as `metric_screw` are stable.
- Millimetres remain the current modelling unit; translations do not change units or decimal parsing rules.
- Backend validation and OpenSCAD diagnostics may still appear in English; full server-side localization is a future task.
- CAD field enum values (e.g. `socket`, `hex`) remain technical identifiers in this initial interface. Future selector widgets should show localized labels while sending canonical values.
- Add other languages by extending the translation catalog with matching keys. Future production tooling may adopt an established i18n package to support pluralization, translations and locale-specific formatting.
